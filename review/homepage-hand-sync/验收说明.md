# 首页大手 · 交互同步修复验收（第二轮）

范围：只修「手势与文件夹切换脱节」及相关遮挡/首屏问题。保留已验收的大手 SVG、主文件夹 SVG、字体、响应式尺寸与 3.4 秒 Intro 轨迹。

## 1. 三个根因（均有实测证据）

### 1.1 大手「冻在原地」的直接成因：Intro 动画结束后没有被取消

Intro 用 WAAPI 播放，参数是 `fill: 'both'`。播放结束后动画对象仍挂在元素上，**动画效果在 CSS 层叠中高于内联样式**，于是此后写进 `actor.style.transform` 的任何姿势都被 3400ms 关键帧覆盖。

诊断证据（`review/homepage-hand-sync/debug-drag.mjs`）：拖动进行中，内联样式已是
`translate(-303.507px, 161.542px) rotate(-9.6958deg)`，而 `getComputedStyle` 仍返回
`matrix(0.990268, 0.139173, …, -185.016, 765.765)`——正是 Intro 末帧 `x=.025, y=.98, rot=8°` 的坐标。

修复：Intro 结束、被接管、被隐藏时都显式 `cancel()`，并给 `motion.finished` 挂空 catch（取消不该冒泡成未处理拒绝）。

### 1.2 结构性问题：手势层根本没接 Carousel 状态

原 `hand-guide.js` 只在用户输入时 `stop()`，从不读取拖动进度、切换方向或索引。所以即使修好 1.1，文件夹在动、大手也不会动。

修复：`app.js` 派发交互状态事件，手势层只订阅、不猜测、不自己计时。

### 1.3 首屏中央文件夹空白

`style.css` 顶部的 `@import url("fonts.googleapis.com/…")` 是**渲染阻塞**样式表，它连带阻塞 `type="module"` 的 `app.js` 执行。实测：

| 场景 | 文件夹 SVG 注入 | 首次绘制 |
|---|---|---|
| 改动前 | 877 ms | 1812 ms |
| 改动后 | 101–121 ms | 120–144 ms（热态） |

另外 `await document.fonts.ready` 没有上界：录屏时实测字体请求挂住，Intro 会永远不播。改为 `Promise.race(…, 1200ms)`。

字体族、字重、`display=swap` 全部不变，只是改为在 `index.html` 用 `media="print" → onload` 异步加载，并保留 `<noscript>` 回退。静止画面与改动前 checkpoint **逐字节一致**，可反证字体仍在生效。

## 2. 手势状态契约

`app.js` 新增一个极小的状态广播，手势层是唯一订阅者。Carousel 的原有动画、布局、索引逻辑未改。

| 事件 | 触发点 | 载荷 |
|---|---|---|
| `drag-begin` | 指针按下 | — |
| `drag-move` | 每帧拖动（原 `follow()` 内） | `offset, progress, direction, to, distance, atBoundary` |
| `drag-end` | 释放（含竖向手势与取消） | `axis, cancelled, dx, willSwitch, direction, to` |
| `switch-start` | `settle()` 内、文件夹开始运动之前 | `from, to, direction, distance, dx, duration` |
| `switch-cancel` | `settle()` 判定回弹（方向 0） | `from, to` |
| `switch-end` | 切换完成 | `from, to, direction` |

因此手势的启动时间点与文件夹主切换阶段是同一个同步调用栈，不存在两个各自 setTimeout 对表的情况。边界按键/滚轮不触发 `settle()`，因此不会播完整切换手势。

## 3. 四态与位移映射

- **Intro**：3.4 秒已验收轨迹原样保留（同一组关键帧、分段 easing、同一尺寸公式）。
- **Interactive（拖动）**：`p = clamp(offset / (可见宽 × .45), -1.4, 1.4)`
  - 水平：`x = READY.x + p × .20`
  - 旋转：`rot = p × 15°`（左移左倾、右移右倾，与 Intro 方向约定一致）
  - 纵向：`y = READY.y + min(1,|p|) × .03`（随拖动略沉，不遮挡信息）
  - 反向拖动 → `offset` 变号 → 大手反向，无需额外分支。
- **Swipe（滚轮/方向键/拖动释放后的吸附）**：与切换同时启动，`sign = -direction`；下一个文件夹大手向左拨走，上一个向右。前 42% 推出、随后弹性回收（`easeOutBack` 轻微过冲）、58% 后下沉淡出，总长 640ms，与 Carousel 自身的 `duration` 对齐。
- **Spring（回弹/点击/低于阈值滚轮）**：从当前姿势弹回 `READY` 并下沉淡出，520ms。
- **Hidden**：`anchor.hidden = true`、清空内联样式、停掉 rAF、取消任何残留动画。静止 DOM 与改动前一致。
- **接管平滑**：`takeOverIntro()` 先读取实时矩阵反解出姿势，再取消 Intro，然后用同一个渲染循环从该姿势继续；接管后 280ms 内响应度从 16% 渐入到 100%，避免第一帧"追上"造成跳变。实测单帧最大位移由 71.1px 降到 44.5px。
- **兜底**：可见但既无拖动、无手势、也无 Intro 时，700ms 后强制隐藏，杜绝"长期遮挡"。
- **切回 CV**：Intro 一次页面加载只播一次，返回 CV 不重播；真实拖动/切换仍可唤出手势。

## 4. 遮挡与重复提示

- 大手在场期间（Intro / Interactive / Swipe / Spring / Exit 全程）小黄手 `visibility: hidden`；退出后恢复。
- 编号、职业描述、滑动引导、页脚的层级保持在大手之上（沿用原有临时层级规则，未移动任何元素）。
- 大手只在有交互时出现，静止即 Hidden，不存在长期遮挡。
- 未通过缩小大手来解决问题。
