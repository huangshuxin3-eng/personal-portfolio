# 中央文件夹取消回弹消失：定向修复

## 根因与复现

Git baseline：3e8ddfa432aef12c6e72d0acb88e175d1b09a14f。当前未提交的 380ms 擦切版本上，仅修复取消分支的裁切终点。

原录屏 motion-desktop.webm 的约 10.72–11.16 秒对应现有 record.mjs 的 Scene 4：当前 CV，左拖 92px（6 步、每步间隔26ms），停留420ms，再松手。距离小于100px提交阈值；停留使100ms速度窗口内没有有效快速移动，因此不切换，进入 direction=0 的420ms回弹。

错误代码：当前文件夹的回弹终点使用 cuts(1,0).incoming，即 inset(0 0 0 100%)。这是“待进入片完全隐藏”的裁切，而不是“当前片完全打开”。待进入片同时也收回到100%隐藏；于是两片都被裁空。420ms结束后reset()清掉clip-path，当前CV才瞬间完整恢复。

不是 current 索引被错误切换，也不是大手控制文件夹或旧WAAPI残留。复现时index一直为0，aria-busy=true；错误裁切来自本次新建的420ms回弹动画。完成后原实现同样会清掉动画，故此前只检查最终状态的测试漏掉了回弹中间消失。
